## Step 2 — build the scrub

Structure (per spec, don't deviate without reporting why):
- A tall wrapper (~`175vh` per "~1.75× viewport height of scroll") containing a
  `position: sticky; top: 0` (or Tailwind `sticky top-0`) inner viewport-height panel.
- `useScroll({ target: wrapperRef, offset: [...] })` from `framer-motion` to get scroll
  progress `p` through that wrapper (not the whole page).
- Four visual stages driven by `useTransform(p, ...)`, per the spec's exact ranges:
  - `p 0.00–0.15`: one centered monochrome prompt bubble. Caption 0 ("You ask once.").
  - `p 0.15–0.45`: prompt splits into 4 horizontal lanes, each gets a model-chip header
    (mono font — `content.councilDemo.models[].id`) and streams its canned `lines`. Active
    lanes pulse `--live` (`text-brand`/`border-brand`, using CSS animation or Framer
    `animate` on opacity, not color transitions that fight the reduced-motion story).
    Caption 1 ("Every model answers at once.").
  - `p 0.45–0.70`: lanes finish on a stagger, each settles from pulsing `--live` to steady
    (no more pulse, but stays visually "done" — e.g. a static green checkmark or border,
    not fading to gray yet — the spec's exact wording is "green settles to steady," i.e.
    still green, just not animating).
  - `p 0.70–1.00`: 4 lanes converge into one centered "chair" card assembling
    `councilDemo.synthesis.lines`. Green fades to `--ink` (`text-brand` → `text-foreground`)
    as it finishes. Caption 2 ("One neutral answer, synthesized.").
- Monochrome except the `--live` pulse — no per-model color coding. This is explicit in
  the spec and easy to accidentally violate by giving each lane a "friendly" distinct
  color; resist that.
- Animate `transform`/`opacity` only (GPU-composited) — no animating `width`/`height`/
  `top`/`left` for the lane movement; use `x`/`translateX` via Framer's `motion.div style=
  {{x: ...}}`.

## Step 3 — reduced motion

Per spec: "End state = reduced-motion static state: the final composition (prompt at top,
four faded lanes behind, synthesis card in front) rendered statically and legibly, with the
three captions shown as plain labels." Implement via a `prefers-reduced-motion` media-query
check (there's precedent in this codebase — `model-council-diagram.tsx` lines ~21–27 use
`window.matchMedia("(prefers-reduced-motion: reduce)")` with a change listener; reuse that
pattern rather than inventing a new one) that short-circuits the scroll-scrub entirely and
renders the static end-composition with all three captions visible as plain stacked text,
no pinning, no scroll-driven behavior, no JS animation loop running.

Also handle "renders sensibly before JS hydrates" (spec §5): the default/no-JS DOM should
already be the static end-state described above, with Framer Motion progressively
enhancing it once mounted — don't render an empty shell that only populates on mount.
