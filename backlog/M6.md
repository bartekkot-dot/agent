# M6 — Reduced-motion / both-theme / mobile / build final pass

Depends: M3, M4, M5 (all animated moments must exist before a final pass over all of them
makes sense). Source: `MOTION-SPEC.md` §5, §8, §9.6.

## Step 1 — verify before changing

This item is verification-and-fix, not new features. Re-read every completion note left by
M1–M5 first — they'll tell you what was already checked at each stage vs. deferred to this
final pass, and any open TODOs (unconfirmed model IDs, unconfirmed stats, the ValueSection
placement decision) that must be resolved before this is truly "done."

## Step 2 — reduced-motion sweep

Go through every animated moment (M3 scroll-scrub, M4 hero demo + its replay/re-enter
trigger, M5's two micro-moments, plus the pre-existing `Reveal`/`.glow-orb-animate`/
`model-council-diagram.tsx`-style animations if any survived M2's cuts) with
`prefers-reduced-motion: reduce` forced on, and confirm every single one collapses to its
documented static end-state with **zero** JS animation loops still running (check via
browser dev tools / a quick `getComputedStyle` or animation-count check, not just visual
inspection — a paused-but-still-scheduled animation can still cost battery/CPU even if it
looks static).

## Step 3 — both-theme sweep

Screenshot every section, both themes, at rest and mid/post-animation where applicable.
Specifically re-verify:
- AA contrast on every green-on-background pairing, especially light mode
  (`--live` = `#158A4E` on `--canvas` = `#FFFFFF`, and on `--surface` = `#F5F7F3`).
- The light-mode glow gotcha (M1 Step 4) still holds now that M4's hero demo may render
  additional green elements near the glow.
- No section reads as unfinished/placeholder in either theme.

## Step 4 — mobile responsive pass

Test at a narrow viewport (~380px per the original brief's responsive-pass note). The M3
scroll-scrub and M5 provider grid are the highest-risk items for cramped mobile layout —
confirm the scrub's four lanes don't overlap illegibly on narrow screens (may need a
simplified mobile variant — if so, this is a real design decision, not a trivial CSS
tweak: report it rather than silently shipping a degraded mobile experience) and the
provider grid reflows sensibly.

## Step 5 — final build + a11y floor

`npm run build` clean. Check: visible keyboard focus on every new interactive element
(replay button, nav links, any new links/buttons M2–M5 added), alt text / aria-hidden
correctness on the new SVGs and decorative elements, landmark structure still sensible
after the section reorder.

## Step 6 — report and stop

This is the last item in the backlog. Summarize the full arc (M1–M6) in the completion
notes, list any items deliberately deferred or left as open follow-ups (e.g. if mobile
needed a genuinely different scrub layout that wasn't built), and confirm overall
`Definition of done` against `PLAN.md`'s own list (adjusted for what this addendum changed)
before declaring the redesign complete.
