## Step 2 — build the scripted demo

A **canned, deterministic** ~3.5s sequence (no live API calls, no randomness — same fixed
timing every load and every replay), driven by `content.councilDemo`:

1. Prompt (`councilDemo.prompt`) appears with a typed-in effect in a single input bubble.
2. Four model chips appear (`councilDemo.models[].id`, mono font — this project doesn't
   currently import a mono font; check `src/index.css` for whether M1 or a prior item
   added one, and if not, add JetBrains Mono or similar via the same Fontsource/Fontshare
   pattern used for Cabinet Grotesk in M1, applied only to these chip labels — not
   anywhere else, per the original brief's "mono only for real model IDs, never decorative
   eyebrows" rule, which this codebase currently violates already via the `font-mono`
   eyebrow labels in `features-section.tsx`/`privacy-section.tsx`/`value-section.tsx`
   ("FAQ", "Features", "Privacy", "Pricing Model") — don't fix that pre-existing pattern as
   part of this item, it's out of scope, just don't extend it further here).
   Each chip streams its 2–3 canned `lines` in parallel (stagger the four chips slightly so
   it doesn't read as four identical synchronized blocks — but all should be visibly
   "streaming" concurrently, not sequentially one after another). Each chip glows `--live`
   while its lines are actively streaming.
3. The four panels collapse into one centered "chair" card assembling
   `councilDemo.synthesis.lines`. Green (`--live`/`text-brand`) fades to `--ink`
   (`text-foreground`) once assembled — "finishes" = no longer live.
4. Rests on that final state. **Does not loop.**
5. A small "replay" control (label from `content.hero.replayLabel`) restarts the sequence
   from step 1. Replay also fires automatically if the user scrolls the hero out of view
   and back into view (reuse `src/hooks/use-in-view.ts`, same hook `reveal.tsx` and
   `model-council-diagram.tsx` already use for this exact "did it re-enter view" signal).
